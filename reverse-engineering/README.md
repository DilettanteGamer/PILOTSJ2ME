# Декомпиляция оригинальной Windows-игры

Здесь находится автоматический анализ оригинальных `PILOTS.EXE`, `AUTORUN.EXE`
и `GMW.DLL` из этого репозитория, выполненный Ghidra 11.3.2 PUBLIC.
Это **C-псевдокод, а не восстановленные исходники для сборки**. Имена `FUN_*`,
типы `undefined*`, сигнатуры и границы функций выведены анализатором и требуют
ручной проверки. Отсутствие ошибок декомпилятора не доказывает эквивалентность
псевдокода оригиналу или обнаружение всех функций.

## Результаты

| Файл | Формат | Обнаружено функций | Декомпилировано | Thunk-функций | Ошибок |
| --- | --- | ---: | ---: | ---: | ---: |
| PILOTS.EXE | PE, x86 32-bit | 341 | 327 | 14 | 0 |
| AUTORUN.EXE | PE, x86 32-bit | 84 | 66 | 18 | 0 |
| GMW.DLL | NE, x86 16-bit protected mode | 59 | 26 | 31 | 2 |

Thunk-функции — переходы/обёртки; они перечислены отдельно, без выдуманных
тел функций. Для `GMW.DLL` Ghidra не смогла декомпилировать `1000:07c7`
и `1000:07cd`: `Low-level Error: Overlapping input varnodes`. Их инструкции
сохранены в дизассемблировании. Эти адреса относятся к перекрывающимся
областям обнаруженных функций; корректные границы и соглашения вызова
для этого участка пока не восстановлены.

Для каждого исполняемого файла в `generated/<имя файла>/` сохранены:

* `decompiled.c` — псевдокод с адресами функций и отметками неудачных попыток;
* `functions.tsv` — сигнатуры, статусы и диагностика;
* `disassembly.tsv` — адреса, машинные байты и инструкции;
* `symbols.tsv` — обнаруженные символы, включая внешние импорты;
* `strings.tsv` — определённые Ghidra строки и дополнительная интерпретация
  их байтов в CP1251; кодировка не подтверждена для каждой строки;
* `analysis.json` — счётчики, архитектура, карта памяти и список ошибок.

`generated/inputs.json` содержит SHA-256 исходных файлов и структуру PE-секций.
`PILOTS0.230` — файл данных, не исполняемый код; для него записан только хеш.

У `PILOTS.EXE` конец данных последней PE-секции находится по файловому смещению
`0x11c00` (72704). Далее расположены 48284451 байт добавленных данных.
Их SHA-256 записан отдельно. Они **не декомпилированы и не распакованы**;
этот анализ не устанавливает полный формат игровых ресурсов, сценариев
и анимационных координат. Исходный EXE уже хранится в репозитории, поэтому
добавленные данные повторно не копируются.

Windows-библиотеки GDI32, KERNEL32, USER32 и WINMM не импортировались как
отдельные бинарные файлы. Ghidra использовала доступные встроенные сведения
о типах и таблицы импорта. Системные библиотеки не входят в результат.

## Повторение анализа

Нужны Linux x86-64, Python 3 и **полный JDK 21**, а также Ghidra 11.3.2 PUBLIC.
JRE без `javac` для запуска Ghidra недостаточно. Проверенные дистрибутивы:

* [Ghidra 11.3.2](https://github.com/NationalSecurityAgency/ghidra/releases/tag/Ghidra_11.3.2_build),
  архив `ghidra_11.3.2_PUBLIC_20250415.zip`, SHA-256:
  `99d45035bdcc3d6627e7b1232b7b379905a9fad76c772c920602e2b5d8b2dac2`.
* [Temurin JDK 21.0.8+9](https://github.com/adoptium/temurin21-binaries/releases/tag/jdk-21.0.8%2B9),
  архив `OpenJDK21U-jdk_x64_linux_hotspot_21.0.8_9.tar.gz`, SHA-256:
  `f2dc5418092c43003db8f9005c4a286e1c0104fea96ccdd49e8ebd037cac9219`.

Оба архива получены по HTTPS из официальных GitHub Releases; контрольные
суммы сверены с опубликованными разработчиками. Дистрибутивы инструментов
в этот Git-репозиторий не добавлены.

```sh
export GHIDRA_HOME=/path/to/ghidra_11.3.2_PUBLIC
export JAVA_HOME=/path/to/jdk-21.0.8+9
./reverse-engineering/scripts/decompile.sh
python3 reverse-engineering/scripts/validate_exports.py
```

Сценарий создаёт временный Ghidra-проект, выполняет анализ с ограничением
четыре CPU и 600 секунд на файл, экспортирует текст и удаляет временный проект.
Файлы в `generated/` перезаписываются. Непустой `analysis.json` должен принадлежать
текущему запуску. Известные ошибки GMW не превращаются в успешную декомпиляцию;
они явно сохраняются в отчёте. Вывод Ghidra содержит дополнительную диагностику.
Для каталога настроек Ghidra без записи в домашнюю папку можно установить
`JAVA_TOOL_OPTIONS=-Duser.home=/writable/path`.

В подготовленной облачной среде инструменты установлены в
`/workspace/pilots-tools/ghidra_11.3.2_PUBLIC` и
`/workspace/pilots-tools/jdk-21.0.8+9`. Сценарий был запущен на этой машине.
Проверка экспорта проверяет соответствие исходных файлов, счётчиков,
индекса функций и наличия псевдокода. Игра не запускалась; сборка оригинала
из полученного псевдокода не поддерживается.

## Для дальнейшего восстановления

Разбирать игровую логику следует с сопоставлением вызовов и данных, затем
восстанавливать формат добавленных данных и только после этого — условия
анимаций и их координаты. Готовые J2ME JAR и ранее полученная декомпиляция Java
не использовались вместо оригинальной Windows-игры в этом анализе.
Авторские права оригинальной игры остаются у указанных в её README владельцев;
наличие псевдокода не устанавливает новую лицензию на оригинал.
