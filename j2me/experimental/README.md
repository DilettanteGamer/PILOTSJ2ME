# Экспериментальная 128×160 — 0.27.1

Сборка для повторной проверки на Nokia C1-02 после задержек версии 0.27.0. Вся игра находится в одном JAR, размер около 12,27 МБ (11,70 МиБ). Оригинальная иконка сохранена. RMS `pilots-exp-*` остаётся прежним: экспериментальный прогресс отделён от обычного релиза. Все локации открыты для тестирования.

## Что изменилось

Глобальный банк тайлов требовал распаковывать несколько больших блоков ради одного нового действия. Заменили его независимыми локальными банками: до восьми соседних изображений, целевой объём 64 КиБ. Один большой кадр может потребовать отдельного банка; фактический максимум — 266 240 байт. Тайлы остались 16×16, пиксели, палитры, смещения и тайминги не изменились.

Для часто используемых игровых кадров выбран DEFLATE внутри JAR: распаковку выполняет загрузчик ресурсов Java-машины, без Java-декодера LZMA на каждом действии. Это увеличивает файл относительно локальных LZMA-банков, зато убирает основной источник задержек. Фоны P8, bar и музыкальные MIDI сохраняют LZMA1 со словарём 256 КиБ. MIDI восстанавливаются побайтно, без перекодирования.

Кэш банков ограничен 256 КиБ и четырьмя слотами (один большой банк допускает превышение на 4 КиБ). Дополнительно кэшируются до 96 КиБ готовых кадров. LZMA-декодер переиспользуется с корректным сбросом словаря; вход буферизуется по 8 КиБ. Обычные ресурсы больше не открываются дважды ради проверки формата.

Звук остаётся принятым Opus VBR 8 кбит/с, 12 кГц, SILK-NB/20 мс. Restricted Concentus сохраняет CLDC-порт и лицензии; DSP и пакеты не изменены. Потоковый адаптер выдаёт PCM16/WAV 11025 Гц для MMAPI. Короткие звуки до 32 КиБ после декодирования кэшируются в пределах 64 КиБ: повторные шаги и короткие реплики не требуют повторного декодирования. Длинные реплики остаются потоковыми.

## Проверки и ограничения

Проверены все 1667 анимаций / 20 916 кадров, все 52 ресурса P8/bar/MIDI, все 327 звуков / 29 087 пакетов, побайтное совпадение PCM до/после CLDC-порта, повторное чтение коротких звуков из кэша, переходы, сохранения, меню и отдельные головоломки. JAR проходит проверку CRC, JAD, classfile 45 и CLDC preverification.

На настольной Java сценарий из 40 действий с чередованием анимаций двух героев занимал у 0.27.0 около 9,26 с, у новой сборки — около 0,15 с. Замеры не предсказывают скорость KVM. Окончательные показатели текущего JAR и SHA — в [verification.json](dist/verification.json). Для сравнения: локальные банки с Java-LZMA давали около 0,32 с при размере JAR 10,36 МБ; стандартный релиз — около 0,04 с при размере 19,85 МБ.

MMAPI на компьютере проверяется адаптером, читающим настоящие WAV-потоки; это не проверка MMAPI телефона. Версия 0.27.1 пока не проверена на физическом C1-02. Размер меньше сообщённых 13 МБ свободного места; потребность установщика во временном месте зависит от телефона. Кэши ограничены, но расход всей Java-памяти включает также декодер, текущие кадры, VM и нативные медиабуферы.

## Сборка

Инструменты: `/workspace/pilots-tools/j2me-placement`, JDK 21: `/workspace/pilots-tools/jdk-21.0.8+9`; пути заданы в build-скриптах. Нужны NumPy и Python lzma.

```
python3 j2me/experimental/port_codec.py
python3 j2me/experimental/build_experiment.py
python3 j2me/experimental/run_tests.py
```

По умолчанию используются локальные банки в JAR-DEFLATE. `PILOTS_NATIVE_TILES=0` переключает сборку на локальные LZMA-банки; путь выходного JAR тот же. Этот вариант компактнее, но медленнее. Проверка ActionLatencyTest использует фиксированный список из tests/action-latency-cases.txt; исторические результаты сравнения сохранены в verification.json.

Входной корпус Opus и суженный desktop closure закреплены в input/vendor. Для изменения аудио нужен prepare_audio.py (FFmpeg/libopus) и повторная проверка всех пакетов. Происхождение ядра и лицензии — docs/CODEC_FEASIBILITY.md. Константные ссылки Arrays/AssertionError заменены на CLDC-совместимые ArrayOps/CodecFailure; байткод перепроверен против настоящего CLDC 1.1.
