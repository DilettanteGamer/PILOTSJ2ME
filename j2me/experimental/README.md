# Экспериментальная 128×160 — 0.27.0

Вся игра и ресурсы находятся внутри одного JAR. Отдельные RMS-имена `pilots-exp-*` сохраняют прогресс экспериментальной сборки отдельно от релизной. В экспериментальном меню «Локации» все уровни доступны сразу для проверки; обычные релизы сохраняют разблокировку по прохождению.

* ANM6 сохраняет прежние палитры, кадры, координаты и тайминги. Общие тайлы16×16 хранятся в независимых блоках256КиБ LZMA1. Карты кадров сгруппированы по32 и сжимаются ZIP; два последних набора карт кэшируются. Есть кэш1024 тайлов (256КиБ) и последний распакованный блок. Порядок реконструкции группирует запросы по блокам.
* P8 и MIDI упакованы обратимым LZMA1 и восстанавливаются для прежних загрузчиков. Музыкальные MIDI-байты не перекодированы.
* Restricted Concentus портирован на CLDC API заменой двух ссылок constant pool: Arrays→ArrayOps, AssertionError→CodecFailure. DSP не изменён. Все классы retargeted1.1 и preverified против настоящего CLDC1.1. Сохраняются лицензии.
* Звук хранится как принятый Opus8k/12k/20ms SILK-NB. OPU1 содержит исходную длительность и неизменные пакеты. Потоковый адаптер убирает pre-skip, преобразует12k→11025 и выдаёт PCM16/WAV в MMAPI. Буфер PCM —240 отсчётов; целый звук в Java-массив не распаковывается.
* Повторное использование состояния SDK-LZMA выявило overflow в полном проходе; текущий прототип создаёт чистое состояние декодера для каждого блока. Это корректный, но более затратный по GC вариант. Кэш тайлов уменьшает количество распаковок. Следующий шаг оптимизации — безопасное повторное использование контекста и улучшение локальности банков.

Проверка MMAPI на компьютере использует lifecycle-адаптер, который читает настоящие WAV-потоки и проверяет их системным аудиопарсером. Это не проверка конкретного телефона. Скорость настольной Java не переносится напрямую на KVM. Общие буферы графики требуют примерно0,8МБ плюс кадры, VM, PCM и нативные буферы; на телефоне с малым heap возможны ограничения. Версия предназначена для тестов.

## Сборка

Инструменты берутся из `/workspace/pilots-tools/j2me-placement`, JDK21 — `/workspace/pilots-tools/jdk-21.0.8+9`; пути заданы в двух build-скриптах. Нужны NumPy и Python lzma.

```
python3 j2me/experimental/port_codec.py
python3 j2me/experimental/build_experiment.py
python3 j2me/experimental/run_tests.py
```

Входной корпус Opus и исходный суженный desktop closure закреплены в input/vendor. Чтобы изменить аудио, сначала заново выполнить prepare_audio.py (нужен FFmpeg/libopus), затем повторить все тесты декодера; другой кодек/версия могут менять допустимые пакеты. Происхождение ядра и лицензии — docs/CODEC_FEASIBILITY.md. Новый синтаксис исходников Concentus не переписывается: изолированный проверенный closure переводится на CLDC-совместимые вызовы и байткод с полной перепроверкой PCM.

## Проверки этой сборки

CLDC preverification; SHA всех327 клипов до/после API-порта; все1667 анимаций/20916 кадров; все52 P8/bar/MIDI-ресурса; настоящий WAV-поток через MMAPI lifecycle spy; LocationEntryTest с переходами, RMS и тремя отдельными головоломками. Последняя правка меню открывает список локаций для теста и не меняет графические ресурсы. Настольная проверка4 000 прогретых кадров ходьбы:25мс против9мс у релизного формата; холодные40кадров190мс против15мс. Эти замеры не являются частотой кадров телефона.

Тестовые классы лежат в tests; verify_experiment.py создаёт исходные SHA-фикстуры в /tmp/pilots-exp-tests и проверяет CRC/JAD/classfile target. Для настольного запуска используются стандартные заглушки из j2me/tests/stubs и MIDP API. Полный ресурсный проход может занимать несколько минут из-за холодных блоков.
