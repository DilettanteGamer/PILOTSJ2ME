# Кэш канализации и доступные PNG — 0.27.24

[JAR](dist/half128/Pilots-Experimental-128x160.jar) ·
[JAD](dist/half128/Pilots-Experimental-128x160.jad) ·
[Предыдущая 0.27.23](dist/0.27.23/) ·
[Спрайты для ручной правки](editable/README.md).

Пользователь подтвердил на Nokia C1-02 исправление звука и уменьшение
паузы при выключении света в 0.27.23 (VID_20261028_221327_471).
Они сохранены. Для оставшихся пауз канализации проверены кадры,
повторное чтение банков и вместимость кэша готовых изображений.

## Изменение

Кадры канализации теперь читаются при первом реальном использовании для
отрисовки; метаданные, номера кадров и их исходные размеры/смещения
обновляются сразу. Создание акторов, пропуск кадров при seek и невидимая
часть анимации не требуют чтения пикселей. Готовый общий растр можно
использовать без повторного декодирования. Такой механизм уже применяется
в зверином дворе, теперь он включён и для SewerScene.

В канализации мало пикселей, но много разных маленьких кадров одновременно.
Прежних 64 ключей кэша не хватало для циклов крыс и декоративных мышей.
Только для этой сцены доступны 192 ключа, а доля готовых кадров в общем
кэше увеличена с 32768 до 45056 пикселей. **Общий предел остаётся 65536
пикселей**, сырые кадры и банки сохраняют прежние байтовые ограничения.
При переходе в другую локацию возвращаются 64 ключа и раздел 32768
пикселей, ссылки дополнительных RasterCache освобождаются.

Это позволяет использовать ранее свободную часть общего кэша. Его
фактическое заполнение увеличивается: в сценарии ниже 42290 → 59023
пикселя. Таблицы 128 дополнительных ключей требуют около 3584 байт при
четырёхбайтовых ссылках, плюс объекты RasterCache и заголовки Image;
эти расходы не входят в счётчик пикселей. Общее потребление RAM телефона
должно быть проверено на устройстве, оно не объявляется прежним побайтно.

## Проверки

Обычный вход и 400 тиков, сравнение с 0.27.23:

| Работа | 0.27.23 | 0.27.24 |
| --- | ---: | ---: |
| Прочитанные банки | 377 | 40 |
| Открытия прочих ресурсов | 999 | 95 |
| Несжатые байты банков | 5437442 | 573698 |
| Создания Image | 1451 | 153 |
| Пиковые байты банков | 66304 | 70656 |
| Пиковые байты кэша сырых кадров | 96494 | 97624 |

Отдельно за 200 тиков после прогрева: Image 720 → 12,
повторные чтения банков 182 → 0. Оставшиеся небольшие вытеснения готовых
изображений допускаются в пределах общего лимита памяти.

Картинка и сериализованное состояние сравниваются по SHA-256 на каждом
шаге 400 тиков, а затем при настоящем столкновении, сохранении/загрузке
падения, плавании, подъёме по лестнице, реплике и возвращении на старт.
Все хеши совпали с 0.27.23. Проверены прохождение канализации, три мыши,
маски ударов, безопасные точки и возврат обычных настроек кэша при выходе.
Полный уменьшенный корпус графики, маршруты, сохранения, головоломки,
меню, полёт, финал и синхронизация аудио также прошли проверки.

Все графические и звуковые ресурсы остались побайтно прежними. Изменения
затрагивают загрузку/кэш и не добавляют новые уменьшенные варианты.
JAR — 9091631 байт (+178 к 0.27.23).

Стенд — JVM с MIDP/MMAPI-заглушками, heap 32 МиБ. Счётчики показывают
объём работы, а не FPS или точную RAM Nokia. Одинаковые значения получены
для неподвижного курсора и сценария изменения его координат; камера
самой канализации остаётся фиксированной. Проверять на телефоне стоит
сначала движение крыс, затем проход, падение/возвращение и выход в
следующую локацию. Счётчики оставлены на экране.

## PNG

Доступны полный архив ANM-спрайтов (34,3 МБ) и небольшой архив канализации
(0,95 МБ). В обоих есть текущие уменьшенные PNG, исходные кадры для
сравнения, браузерный список анимаций и manifest с ID/смещениями.
Архив нужно распаковать на компьютере, затем открыть index.html.
Изменённые PNG можно передать с прежними именами для сборки; JAR
автоматически не импортирует правки. Подробности — в инструкции выше.

Воспроизведение:

```sh
python3 j2me/experimental/build_halfsize.py
python3 j2me/experimental/test_halfsize.py
python3 j2me/experimental/export_sprites.py --include-originals
```
