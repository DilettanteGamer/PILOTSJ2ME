# Первая локация: игровые механики 0.4.1

Продолжение: [0.4.2 — чайник, инвентарь, бочка и кот](FIRST_LOCATION_ITEMS.md).
Ниже описан срез окна 0.4.1; его правила сохранены в новой сборке.

Взаимодействие с окном теперь следует восстановленным правилам оригинала.
Исправлены исчезновение ставней во время открытия и повторный стук Шефа
по открытому окну. Перенесены событие появления вороны, конец сценария
открытия и сохранение промежуточных состояний.

## Управление и действия

«Продолжить» открывает сцену 02 у зоопарка. `1` — Шеф, `3` — Коллега,
`2/4/6/8` — курсор, `5` или касание окна — основное действие. Курсор
над окном жёлтый. `0` — меню, сохранение и загрузка; `*` — масштаб.
Прежний каталог анимаций и просмотр остальных фонов через `7/9` сохранены.

| Окно | Герой | Правило оригинала | Действие |
| --- | --- | --- | --- |
| Закрыто | Шеф | Объект 23, правило 10 → действие 18; объект 17, правило 29 | Стук, ID 86 |
| Закрыто | Коллега | Объект 23, правило 11 → действие 18; объект 18, правило 16 | Открытие, ID 64 |
| Открыто | Шеф | Объект 24, правило 1 → действие 13; объект 17, правила 3/4 | Общая реакция Шефа, исходный ID 36 или 34; стука нет |
| Открыто | Коллега | Объект 24, правило 13 → действие 19; объект 18, правило 30 | Заглянуть, ID 87 |

Это основное действие оригинальной команды `v1c=2`. В срезе 0.4.1 другие предметные режимы оригинала
ещё не включались; режим 3 (чайник) добавлен в 0.4.2. Например, исходные правила различают команды 3/4/5,
но назначать им новые значения в интерфейсе без восстановления всей цепочки
не стали. Условие завершённого подхода (`v88=1`, проверка клетки героя)
пока выполняется постановкой выбранного героя в точку взаимодействия;
полноценная ходьба остаётся следующей задачей.

Реакция Шефа выбирается исходной переменной `v08`: при 0 — клип 36,
при 1 — клип 34. Её значение в текущем порте по умолчанию 0; исходная
цепочка изменения этой переменной ещё не перенесена. Обе ветви извлечены
и проверены по исходным предикатам. Звук и реплики пока не воспроизводятся.

## Последовательность открытия

| Шаг сценария | Команда оригинала | Изменение |
| --- | --- | --- |
| 1 | Объект 18, правило 16: `native13(64)`, `native14(5)` | Коллега начинает открытие, отдельный объект закрытого окна удаляется; створки видны в кадрах ID 64 |
| 13 | Объект 18, правило 17: `native14(6)` | В той же точке появляется объект открытых ставней 24, ID 63 |
| 38 | Объект 18, правило 18: `native14(7)` | Появляется объект вороны 15 в `(320,112)`, его входной сценарий запускает ID 66 |
| 88 | Объект 18, правило 22 | Сбрасываются действие и счётчик, Коллега снова доступен |
| Конец ID 66 | Объект 15, правило 0: `native13(65)` | Ворона переходит в неподвижную позу |

Шаги выполняются с фиксированным интервалом 100 мс. Шаг 1 соответствует
нулевому кадру. На шаге 13 отображается кадр 12 и открытые ставни. После
последнего кадра ID 64 персонаж удерживает позу до конца исходного сценария
на шаге 88. Ворона заканчивает полёт независимо: управление Коллегой
освобождается раньше перехода вороны в неподвижную позу.

В 0.4.0 закрытые ставни скрывались до конца клипа, а открытые появлялись
только после него. В части кадров Коллеги самих ставней уже нет — поэтому
они исчезали. Теперь их отдельный объект возвращается на исходном шаге 13
и остаётся видимым во время оставшейся части действия.

[Неподвижные снимки исправленных слоёв](../j2me/analysis/window-gameplay-0.4.1.png).
Это иллюстрация композиции, а не запись с телефона.

## Что взято из оригинального кода

[Проверяемые данные правил](../j2me/analysis/window-original-rules.json)
содержат SHA-256 оригинального EXE, смещения записей, исходный байткод,
события и восемь проверочных случаев.

`j2me/extract_window_gameplay.py` при сборке читает оригинальный `PILOTS.EXE`:

- Разбирает выбранные предикаты 0x2b и действия 0x2c объектов 17/18/23/24
  секции 4. Ограниченный проверочный интерпретатор выполняет их байткод
  и получает ожидаемые переходы независимо от Java-реализации.
- Проверяет завершение на исходных шагах 13/14/36/88 и команды событий
  открытия/появления вороны. В проверочных случаях подход уже завершён;
  это не полный интерпретатор исходной Windows VM.
- Из общей секции 1 извлекает исходные клипы 12/16 (неподвижные позы)
  и 34/36 (общие реакции Шефа), отсутствовавшие в JAR. Таблицы 0x42 задают
  опорные смещения, записи 0x43 — индексированные пиксели. В JAR используется
  пространство ID `20000 + исходный ID`, чтобы не смешать их с клипами сцены.
- Проверяет закреплённый SHA-256 EXE перед извлечением. Цвета берутся из
  общей для уже перенесённых ресурсов сцены палитры.

Диспетчер исходной VM — `00408e64`, таблица native API — `0041030c`.
`native13` запускает клип текущего объекта; `native14` выполняет связанные
изменения карты. У окна корень `(128,224)`, у действующего персонажа
`(192,304)` — [предыдущее исследование координат](ANIMATION_PLACEMENT_0.3.6.md).

## Сохранение и пауза

Сохраняются открытое окно, выбор и позиции героев, текущие действие и шаг,
а также стадия и кадр вороны. Сохранение посреди открытия возобновляет его
с того же шага; ставни не исчезают и событие вороны не теряется. При уходе
на другой фон сценарий замораживается и продолжается после возвращения.
Меню также ставит его на паузу. Выбор героя, повторное действие и запуск
предпросмотра блокируются до завершения действия персонажа.

Старое сохранение 0.4.0 с открытым окном трактуется как уже завершённое
открытие: ворона находится в неподвижной позе. Закрытое окно остаётся
закрытым. Размер и заголовок сохранения PSV1 прежние: 299 байт.

Внутренние слоты порта в `GameState.variables`:

| Слот | Значение |
| --- | --- |
| 51 | Перенесённое значение исходного `v08` для общей реакции Шефа |
| 52/53 | Клип действия и шаг исходного сценария |
| 54–57 | X/Y Шефа и Коллеги |
| 58 | Маркер схемы полей порта |
| 59 | Кадр полёта вороны |
| 60/61 | Выбранный герой / открытое окно |
| 62 | Ворона: отсутствует / летит / сидит |

Это внутреннее размещение полей порта, не адреса исходных переменных VM.

## Сборка и проверки

Полный JDK и Python 3.9+, сеть для первой загрузки закреплённых инструментов:

```sh
export JAVA_HOME=/path/to/jdk
./j2me/build.sh
python3 j2me/analyze.py
# Необязательная иллюстрация, требует Pillow:
python3 j2me/render_window_gameplay.py
```

ECJ компилирует Java 1.3 в class 45.3 с API CLDC 1.1 / MIDP 2.0; ProGuard
выполняет CLDC preverification без оптимизации, сокращения или обфускации.
URL и SHA-256 инструментов — в `j2me/toolchain.json`.

Проверки новой логики сравнивают восемь случаев с результатами выполнения
исходного байткода: оба героя, оба состояния окна, обе ветви общей реакции.
Проверяются промежуточные события, блокировка повторного действия, сохранение
и миграция. Интеграционные проверки обоих профилей охватывают слой ставней
до/после шага 13, появление вороны, независимый конец её полёта, возобновление
сценария и отсутствие стука по открытому окну.

Общая повторная проверка ранее восстановленных анимаций не выполнялась.
Проверены изменённые игровые переходы и связывание слоёв. Существующие
визуальные ресурсы сохранены побайтово, включая координаты предпросмотра
0.3.6 и исключение «Детали». Проверка на телефоне/эмуляторе не выполнялась.

Сборки обоих профилей, JAD и отчёты: `j2me/dist/`.

## Следующие задачи

1. Перенести подход к объектам и маршруты обоих героев вместо мгновенной
   постановки в точку. Пока второй герой при занятой точке отводится на
   начальную отметку; общую систему навигации и разрешения столкновений
   оригинала ещё предстоит восстановить.
2. Восстановить команды интерфейса 3/4/5, связать их с предикатами объектов,
   перенести исходные флаги сюжета и условия общих реакций.
3. Перенести сторожа, ворота, бочку, кота и предметы по исходным цепочкам
   состояний, затем условия выхода с первой локации.
4. Реакции 14, 15, 21, 22, 27, 28, 30 подключать при переносе конкретных
   правильных/неправильных действий. Их условия пока не заменены догадками.
5. Проверить полные игровые цепочки на обоих разрешениях и устройствах.
