# Первая локация: начало игровых механик, 0.4.0

Первая реализация взаимодействия у зоопарка (сцена 02) теперь собирается из
Java-исходников. В ней можно выбрать героя и взаимодействовать с окном;
открытые створки сохраняются при выходе со сцены и в RMS-сохранении.
Полная головоломка первой локации ещё не перенесена.

## Что доступно

При запуске выберите «Продолжить»: открывается сцена 02, курсор направлен
на окно. `1` выбирает Шефа, `3` — Коллегу. Перемещение курсора — `2/4/6/8`,
действие — `5` или касание окна. Курсор над окном становится жёлтым.
Активный герой и доступное действие подписаны на нижней панели.

| Состояние | Герой | Действие | Результат |
| --- | --- | --- | --- |
| Окно закрыто | Шеф | Стучит, анимация 16 / ID 86 | Окно остаётся закрытым |
| Окно закрыто | Коллега | Открывает, анимация 05 / ID 64 | После завершения открываются створки |
| Окно открыто | Коллега | Заглядывает, анимация 17 / ID 87 | Открытое состояние сохраняется |
| Окно открыто | Шеф | Стучит, анимация 16 / ID 86 | Состояние не сбрасывается |

На время действия повторное нажатие и смена героя блокируются. Меню
приостанавливает действие; после возврата оно продолжается. Просмотр
анимаций доступен после завершения действия. Переход на другую сцену
отменяет незавершённое действие, не открывая окно. Сохранение в ходе
действия записывает только уже завершённые изменения; при загрузке
незавершённое действие не возобновляется.

`0` открывает меню с сохранением, загрузкой и прежним каталогом анимаций.
`7/9` и пункты меню сохраняют возможность просмотра остальных фонов.
Полноценное взаимодействие пока есть только с окном на сцене 02.

## Основания и границы реализации

По сообщению пользователя все анимации восстановлены и уже проверены.
Их воспроизведение повторно не тестировалось. Существующие `.anm`, фоны
и панели сохранены побайтово; координаты предпросмотра 0.3.6 сохранены.

Пользователь указал назначение анимаций: 05 открывает окно, 16 стучит,
17 смотрит в окно. Координаты взяты из предыдущего анализа ресурсов
оригинала: [совмещение окон](ANIMATION_PLACEMENT_0.3.6.md).
Объект окна находится в `(128,224)`, поза действующего героя — `(192,304)`.
Статические состояния используют уже имеющиеся ресурсы 62/63. Пока
проигрывается открытие, отдельные закрытые створки скрываются: створки
входят в кадры самого действия.

**Таблица выше — явно заданные правила первого прототипа.** Точные
предусловия этих действий в оригинальной головоломке ещё не восстановлены.
Из декомпиляции пока нельзя заключить, что Коллега должен открывать окно
без дополнительных условий. Этот фрагмент не выдаётся за точный перенос
оригинального сценария и не открывает ворота.

Ходьбы пока нет: выбранный герой сразу ставится в точку взаимодействия,
второй возвращается на начальную отметку, чтобы персонажи не перекрывали
друг друга. Для неподвижных поз используются первые кадры имеющихся
ресурсов 75/76. После входа на сцену и загрузки позиции героев сбрасываются
на начальные; сохраняются выбор героя, окно и прежняя позиция курсора.

Условия реакций 14, 15, 21, 22, 27, 28, 30 не выдуманы и пока не включены.
По прежнему уточнению пользователя их нужно подключать вместе с
соответствующими игровыми механиками. Позиции предпросмотра 27/28 у ворот
сохранены. «Деталь» по-прежнему исключена из каталога и сборки.

## Код и сборка

- `j2me/src/pilots/` — компилируемое дерево, восстановленное из CFR-вывода
  JAR 0.3.2. Исправлены неструктурированный `AnimationClip.paint`, недостижимый
  `break` в цикле движка и отсутствующий в CLDC тип `FilterInputStream`.
  Исходная декомпиляция в `analysis/decompiled/` оставлена как материал анализа.
- `ZooLogic` — выбор героя, переходы окна, блокировка незавершённого действия.
  Слоты `GameState.variables[60]` и `[61]` выделены для выбора героя и окна;
  это собственные поля порта, не индексы переменных оригинальной Windows VM.
- `ZooScene` — связывание состояния с ресурсами и завершением действия.
  Область окна задана в мировых координатах: `[150,218) × [224,290)`.
  `.hot`-пакеты по-прежнему пусты: эта первая область реализована в Java.
- Существующий формат PSV1 на 299 байт сохранён. Старые сохранения с нулями
  в этих слотах означают Шефа и закрытое окно.
- `build_game.py` — ECJ 4.6.1, Java 1.3 → class 45.3, библиотеки CLDC 1.1 / MIDP
  2.0, затем ProGuard 6.2.2 `-microedition` для CLDC preverification.
  Сжатие, оптимизация и обфускация байткода выключены.
- `toolchain.json` фиксирует URL и SHA-256 инструментов. При первом запуске
  они скачиваются в кэш вне репозитория, затем проверяются по SHA-256.

Нужны Python 3.9+, полный JDK и сеть для первого заполнения кэша:

```sh
export JAVA_HOME=/path/to/jdk
./j2me/build.sh
# Необязательно: --profile 240x320 --tool-cache /path/to/cache --out /tmp/pilots-dist
python3 j2me/analyze.py
```

Сценарий запускает тесты состояния и проверки связывания ресурсов обоих
профилей без экрана. Проверены выбор героя, блокировка, отмена, отложенное
открытие, повторное действие, границы области, сохранение/загрузка и
восстановление статических створок. В проверках завершение действия
инъецируется напрямую: существующие анимации не проигрываются повторно.
Проверяются также CRC JAR, версия классов, наличие ресурсов и сохранность
их байтов. Проверка на телефоне или в эмуляторе здесь не выполнялась.

Результаты сборки: `j2me/dist/Pilots-128x128.jar`, `Pilots-240x320.jar`,
соответствующие JAD и отчёты. Историческая ресурсная упаковка остаётся
доступна как `python3 j2me/build.py --out /tmp/pilots-resources-0.3.6`.

## Следующие игровые задачи

1. Восстановить начальное состояние сцены и условия оригинальных действий:
   сопоставить объекты, предикаты 0x2b, сценарии 0x2c и переменные Windows VM.
   Зафиксировать для каждого действия условия, изменение состояния и реакцию.
2. Перенести ходьбу обоих героев: проходимость, маршруты, направление,
   очередь «подойти → выполнить», сохранение позиций и реакцию на отмену.
3. Подключить сторожа, ворота, бочку, ворону, кота и предметы только по
   восстановленным правилам; заменить временные условия окна оригинальными.
4. Ввести предметы и действия инвентаря, зависимости головоломки и выход
   из первой локации. Реакции привязывать к текущей позиции исполнителя,
   отдельные эффекты ворот — к объекту ворот.
5. Проверить именно игровые цепочки на целевых устройствах обоих профилей:
   паузу, сохранение в разных состояниях, повторные действия и переходы.
