# Первая локация: чайник, бочка и кот — 0.4.2

Текущая версия: [0.5.0 — первая локация до конца и нижняя панель](FIRST_LOCATION_0.5.0.md).
Ниже сохранён исторический срез соответствующей сборки.

Продолжение [переноса окна 0.4.1](FIRST_LOCATION_GAMEPLAY.md). Добавлены первый
предмет инвентаря и исходная цепочка «чайник → бочка → кот → ворона → бабочка».
Окно и открытые ставни работают по прежним исправленным правилам.

## Что доступно игроку

Чайник лежит у двери слева от бочки. Его может взять любой герой обычным
действием: `5` или касанием. Предмет исчезает со сцены в момент исходного
события подбора и появляется в инвентаре.

Инвентарь открывается клавишей `#`, касанием нижней панели или пунктом меню
«Инвентарь». Выбор «Чайник» включает применение предмета к следующему
указанному объекту; «Без предмета» возвращает обычное действие. Выбранный
чайник указан на нижней панели. Переключение предмета и героя блокируется,
пока выполняется действие персонажа.

| Объект и действие | Шеф | Коллега |
| --- | --- | --- |
| Взять чайник | ID 75, получение на шаге 8; конец на 10 | ID 76, получение на шаге 4; конец на 6 |
| Бочка без выбранного предмета, кота ещё нет | Общая реакция без изменения сцены | ID 83, конец на шаге 45 |
| Применить чайник к бочке, кота ещё нет | ID 69; на шаге 25 появляется кот; конец действия на 34 | Реакция ID 84; кот не появляется |
| Бочка, пока кот находится на крыше | С чайником новое действие не начинается; без него — общая реакция | Общая реакция; кот повторно не создаётся |
| Применить чайник к окну | Общая реакция Шефа | Реакция ID 84 в позиции Коллеги у окна |

Чайник при использовании не расходуется. Новое действие по бочке с чайником
можно выполнить после завершения текущей последовательности кота.
Реакция ID 84 привязана к положению выполняющего действие персонажа,
а не к координатам каталога предпросмотра.

## Связь с вороной и порядок действий

Кот появляется в исходной клетке `(192,176)`. Его дальнейшая цепочка зависит
от наличия объекта вороны `(320,112)` в момент начала сценария кота:

- Если вороны нет, кот выполняет короткую последовательность и исчезает.
  Бабочка не появляется. Чайник остаётся у игрока, поэтому попытку можно повторить.
- Если ворона есть, на счётчике 15 запускается ID 67, на 32 — ID 89 и
  удаляется ворона, на 45 создаётся бабочка в `(256,272)`, на 58 запускается
  падение ID 101. Кот удаляется после завершения этой части сценария.
- Бабочка сначала использует ID 90, затем остаётся как ID 91. Её дальнейший
  подбор и применение пока не перенесены.

Удаление кота после падения принципиально для повторной попытки. Оно записано
в метаданных последнего правила, а не в его байткоде вызова звука. Если смотреть
только на команды действия, объект кота остался бы на карте и блокировал бочку.

Практическая цепочка текущего фрагмента: открыть окно Коллегой, получить
чайник любым героем, выбрать его в инвентаре, применить к бочке Шефом.
Условия вороны проверяются по состоянию объекта, а не по факту просмотра
анимации или её номеру в каталоге.

## Основания в оригинальном коде

[Исходные правила и проверочные случаи](../j2me/analysis/barrel-original-rules.json)
извлекаются при сборке из закреплённого `PILOTS.EXE`. В отчёте сохранены
SHA-256, смещения, исходный байткод и метаданные правил.

| Часть | Правила / данные оригинала |
| --- | --- |
| Подбор чайника | Объект 20, правила 8/9 → действие 15; Шеф 17.19/20/22, Коллега 18.45/46/48 |
| Появление предмета в инвентаре | Карта 41 удаляет объект 20 и создаёт объект 33 в панели |
| Выбор чайника | Объект 33, правило 1: исходная переменная `v1c` становится 3 |
| Шеф с чайником у бочки | Объект 22, правило 14 → действие 27; 17.39/40/45; карта 13 создаёт кота |
| Коллега у бочки | Объект 22, правило 15 → действие 17; 18.55/59 |
| Неправильное применение чайника Коллегой | Действие 24, правила 18.35–38, ID 84 |
| Отказ при коте на крыше | Объект 22, правила 2/3; карта-предикат 11 |
| Свободная точка для нового кота | Карта-предикат 12 |
| Ветвление кота | Объект 16, предикаты карт 8/9; исходные `v94` и `v98` |
| Удаление вороны / появление бабочки | Карты 10 / 43 |
| Удаление кота | Объект 16, правило 13: метаданные 0x199, операция `fe fc 00 00` |
| Статическая бабочка | Объект 30, правило 0, переход с ID 90 на ID 91 |

Это предметный режим исходного интерфейса, а не произвольно назначенное
«второе действие» по бочке. Основной режим использует `v1c=2`, выбранный
чайник — `v1c=3`. Предметы исходных режимов 4/5 ещё не перенесены.

Для общих реакций Коллеги из секции 1 дополнительно извлечены клипы 35/37
(в JAR — ID 20035/20037). Выбор зависит от исходного флага `v0c`; обе ветви
проверяются, начальное значение порта — 0. Цепочка изменения этого сюжетного
флага, как и флага `v08` у Шефа, пока не восстановлена целиком. Звуковые
команды оригинала учитываются при анализе событий, но звук в порте ещё не включён.

## Сохранение и реализация

Поддерживается сохранение посреди подбора, действия по бочке, погони кота
и появления бабочки. После загрузки восстанавливаются этапы и кадры,
исчезнувшая ворона не возникает снова, а предмет не дублируется на земле.
Уход с локации и меню приостанавливают последовательность.

Формат PSV1 остаётся на 299 байт. Старые сохранения 0.4.1 открываются;
новые поля в них равны нулю: чайник ещё лежит на земле, кота и бабочки нет.
Открытое окно и ворона из такого сохранения сохраняются.

Дополнительные поля порта:

| Поле | Назначение |
| --- | --- |
| `inventory[0]` | Чайник получен |
| `variables[40/41]` | Ветка и счётчик кота |
| `variables[42/43]` | Стадия и кадр бабочки |
| `variables[44/45]` | Клип и кадр кота |
| `variables[46]` | Перенесённое значение исходного `v0c` |
| `variables[50]` | Выбран чайник / обычное действие |

Прежние слоты 51–62 описаны в документе окна. Это поля порта, не прямые
адреса исходной VM. В runtime теперь девять одновременно доступных объектов;
ограничение восьми актёров в формате исходного `.act` не изменялось.
Крупные кадры по-прежнему читаются последовательно, а не загружаются целыми клипами.

## Проверки и ограничения

Сборка `./j2me/build.sh` выполняет:

- Прежние 8 проверок окна по исходному байткоду.
- 26 новых проверок по исходным предикатам/действиям: подбор обоими героями,
  бочка с предметом и без него, наличие кота, неверное применение к окну,
  обе ветви общих реакций.
- 7 событий кота по исходным правилам и отдельную проверку удаления
  через метаданные, позволяющего повторную попытку.
- Интеграционные проверки обоих профилей: предмет на земле и в инвентаре,
  координаты исполнителей, неправильный порядок, успешная цепочка,
  сохранение посреди подбора и после удаления вороны, сохранность ставней.

Существующие визуальные ресурсы не изменялись. Проверяется новая логика
сценариев и их связывание; общая повторная проверка восстановленных анимаций
не проводилась. Проверки на устройстве/в эмуляторе здесь не выполнялись.

Сборки 0.4.2 и JAD находятся в `j2me/dist/`, рядом с отчётами.
Полноценная ходьба пока заменена постановкой в исходную точку взаимодействия:
`(64,320)` для чайника, `(192,320)` для бочки. Временный отвод второго героя
с занятой точки сохраняется. Следующие задачи — подбор бабочки, остальные
предметы, связанные правила ворот и навигация персонажей.
