# Совмещение створок с оконным проёмом: 0.3.6

Версия 0.3.5 неверно совмещала оконную анимацию с фоном: ориентиром был
выбран персонаж рядом с проёмом, а не геометрия створок. Эталон пользователя
показал это смещение. В 0.3.6 привязка восстановлена по оконным ресурсам
оригинала и проверена непосредственно по пикселям створки.

## Геометрическое основание

В исходных правилах сцены сущности окна 23 и 24 используют одну точку
`(128,224)` при клетке 64×16. Данные извлечены из оригинального EXE:
[original-scene02.json](../j2me/analysis/original-scene02.json).

У закрытой створки ID 62 смещение `(39,6)`, поэтому её левый верхний угол
на фоне — `(167,230)`. В первом кадре анимации 05 / ID 64 та же створка
находится при frame offset `(-25,-74)`. Отсюда опорная точка персонажа:

```text
(128,224) + (39,6) - (-25,-74) = (192,304)
```

1276 из 1277 непрозрачных пикселей исходной створки совпадают с этим участком
первого кадра анимации. Единственный отличающийся пиксель записан в
[отчёте совмещения](../j2me/analysis/window-alignment.json), а не скрыт.
Это проверка пространственного совмещения ресурсов, не тест проигрывания.

У открытых створок ID 63 смещение `(25,3)`: их группа начинается
в `(153,227)`. Это соответствует расположению створок по обе стороны
проёма на эталоне пользователя. Опорная точка окна `(128,224)` и точка
персонажа `(192,304)` различаются намеренно.

## Что изменено

| Пункт | ID | Anchor в 0.3.5 | Anchor в 0.3.6 |
| --- | ---: | --- | --- |
| 05 — открыть окно | 64 | 200,328 | 192,304 |
| 16 — постучать | 86 | 144,320 | 192,304 |
| 17 — посмотреть в окно | 87 | 144,320 | 192,304 |

В 16 и 17 персонажи теперь стоят справа от окна и обращены к нему,
а не находятся слева и смотрят от него. Их индивидуальные frame offsets
сохранены. Для присутствующего в сцене актёра ID 64 также установлена
точка `(192,304)`. Camera focus обновлён на ту же дельту.

Положения у ворот, другие анимации, Java-классы и все файлы ANM1 сохранены.
Новых условий действий или постоянного игрового состояния «окно открыто»
не добавлено: это относится к будущим механикам. Ресурс ID 63 используется
в статической иллюстрации как эталон; дополнительно в игровой кадр он
этим изменением не внедряется.

## Результат

* [JAR/JAD 0.3.6, оба профиля](../j2me/dist/).
* [Увеличенное сравнение 0.3.5 / 0.3.6 / эталонных створок](../j2me/analysis/window-alignment-0.3.6.png).
* [Общая таблица координат 0.3.6](../j2me/analysis/placement-0.3.6.json).

Статическая иллюстрация показывает первый кадр 05, средние кадры 16/17
и отдельно эталонные открытые створки. Это не запись эмулятора. Проверены
геометрическое совмещение, состав изменённых каталогов, сохранение байткода,
кадров и прочих ресурсов, размер и версия JAD. Воспроизведение не тестировалось
повторно, как просил пользователь.

Воспроизведение проверки из корня репозитория:

```sh
python3 j2me/extract_scene02.py
python3 j2me/verify_window_alignment.py
./j2me/build.sh
python3 j2me/analyze.py
# Необязательные статические иллюстрации, требуют Pillow:
python3 j2me/verify_window_alignment.py --render
python3 j2me/render_placements.py
```
